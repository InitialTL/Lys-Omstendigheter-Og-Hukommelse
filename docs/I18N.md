# Internationalization and research validity

There are two different language layers in this app:

1. **Interface language**. The visitor can change the UI language even after
   registering. The chosen interface language is stored locally, and the
   browser's preferred language is detected on first visit. RTL layout support
   exists for new vetted language packs. Unknown browser locales fall back to
   English instead of guessing or machine translating study instructions.
2. **Graded study language**. Registration locks the language of the object
   labels and answer grading for the entire three-round experiment. This must
   not change when the UI language switcher changes, or results become invalid.

The 12 selectable study languages are **Norwegian Bokmål, English, Swedish,
Danish, Dutch, German, French, Spanish, Italian, Portuguese, Polish and Romanian**.
Every active interface message now has a local, static translation in all
12 languages (see `localeKeys.ts`, `locale-*.ts`, the original Swedish/German/
French/Spanish message map and `locale-original-patches.ts`). Screen-brightness
guidance is localized for each. The registration and header selectors share a
searchable, responsive language picker.

**Important scientific limitation:** Interface completeness is not proof of
native-speaker quality or equivalent word-list difficulty. The additional
languages contain fixed, pretranslated object words and language-specific
grading, but still require independent native-speaker proofreading and
psychometric validation before a definitive study. Analyze language groups
separately as appropriate. No third-party live translation service is used.

To add a new language:

1. Add its BCP 47 code and native name to `frontend/src/i18n.ts` and the
   language picker.
2. Add each displayed string to `localeKeys.ts`, translate all strings in the
   relevant static language pack, and translate brightness-help instructions.
   Run the locale coverage test before declaring interface support.
3. Add translations and accepted synonyms for all 30 targets in
   `backend/words.py` and extend `LANGUAGES` and the registration validation.
4. Verify NFC/NFKD handling, answer normalization, accents and right-to-left
   layout when relevant.
5. Pilot-test word-list difficulty, font rendering, input methods and cultural
   appropriateness with native speakers.
6. Bump the protocol version and analyze the new language as a separate
   condition until comparable difficulty is demonstrated.

Automatic machine translation may be used to **draft** new locale packs, but
must not silently grade live-study answers. The app deliberately contains no
external translation API key or uncontrolled third-party translation calls.
